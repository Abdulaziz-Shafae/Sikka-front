# جاهزية واجهة سكة قبل ربط الباك إند

هذه المرحلة تجهز العرض والتفاعلات محليًا. لا تعتبر بيانات localStorage حسابات فعلية، ولا نتيجة أهلية أو تخطيط حقيقي. أساس التعديل فرع `feat/final-ui-flows`، مع الاستفادة من واجهة Calendar الموجودة في `feature/calendar-export-ready`. لا نشر أو تغيير لفرع main ضمن هذه المرحلة.

## ما صار متاحًا في الواجهة

| الميزة | التنفيذ الحالي | عند الربط |
|---|---|---|
| الاستكشاف دون حساب | كتالوج وخريطة نواف وصور المشروع | استبدال الكتالوج ببيانات Ride/Place الصحيحة |
| SOLO / FRIENDS / FAMILY | تجهيز الزيارة والمشاركين والحضور | معرفات Visit وVisitMember فعلية وصلاحيات الخادم |
| TOGETHER / SPLIT | إعداد TOGETHER للأفراد والعائلة؛ SPLIT للأصحاب واختيارات لكل شخص | اعتماد توزيع الخادم والإشراف الفعلي على القُصّر |
| أولويات كل لعبة | MUST_RIDE / PREFERRED / OPTIONAL مستقلة | preferencesPayload يطابق sourceRideId إلى ID الخادم، بلا اعتماد على ترتيب الكتالوج |
| خصائص لا يرغب بها المستخدم | أفعوانيات/ماء/ظلام/سقوط، مستقلة في SPLIT | إرسال dislikedFeatures في MemberPreferencesDtoIn |
| الوجبات والمطاعم | وجبة60د وسناك30د، وقت ومكان لكل بريك | تأكيد الخيارات المسموحة وPlace IDs وmealPolicy |
| توليد الخطة | شاشة تجهيز ومعاينة محلية مرتبة حسب الأولوية | استهلاك PROCESSING/SUCCEEDED/FAILED من الخادم، دون تشغيل محرك المعاينة للبيانات الحقيقية |
| أسباب الاستبعاد | قسم لكل لعبة مستبعدة، مع أولوية ومشارك وسبب محلي مصرح به | excludedRides.reasonMessage/reasonCode من الخادم؛ لا اختراع أسباب للركوب غير المفسر |
| خطط الأعضاء | عرض القروب/عرضي وتبديل هوية المعاينة لاختبار صلاحيات التصميم | بيانات حساب المستخدم الحالي فقط؛ منع الوصول من الخادم |
| الخريطة المرتبطة بالخطة | ترتيب مرقم، بطاقات تركز المواقع، مسارات graph لكل مشارك | map-route/PER_MEMBER؛ لا خطوط مستقيمة أو مواقع بريك مجهولة مصطنعة |
| اعتماد الخطة والوصول | اعتماد المنظم ووقت الوصول قبل البدء ويوم الزيارة بتوقيت الرياض | تنفيذ approve/arrival/start بالخادم وفحص حالته |
| أثناء الزيارة | سجل لكل مشارك: ACTIVE/COMPLETED/SKIPPED وتصحيح وتقييم بعد الإكمال | ActivitySession وVisitRecord APIs؛ لا استنتاج الإكمال من مرور الساعة |
| إعادة التخطيط | مقارنة الحالي والمقترح؛ لا يتغير الأصل قبل الموافقة، رفض، صلاحيات المنظم | اقتراح الخادم وproposalKey والتحقق من تغيّر البيانات قبل الاعتماد |
| الطعام والصلاة والأعمال المحفوظة | لا تُحرّك في مقترح التوقيت المحلي إذا اعتبرت التزامًا ثابتًا | الخادم مصدر fixed/pinned/completed وأوقات الصلاة المؤكدة |
| النهاية والتقييم | تأكيد الإنهاء دون تعليم الباقي مكتملًا؛ تقييم الزيارة والنظام منفصلان | complete/review/progress والسجل الفعلي |
| تكرار الزيارة | يحتفظ بالتفضيلات ويحذف التخطيط والدفع والسجل والتقييمات من المسودة الجديدة | reuseVisit واستحقاق التعديلات كما يقرره الخادم |
| تعديل/إلغاء/حذف الزيارة | أدوات محلية مع تأكيد الإلغاء/الحذف؛ منع تعديل اختيار معتمد مباشرة | endpoints/cascade/quota rules الفعلية |
| الملف والعائلة | حفظ بيانات الميلاد والطول والوزن والجنس، إضافة وتعديل اسم وحذف فرد محلي | الملف الموثق وسياسة حفظ البيانات الصحية وموافقاتها |
| التحقق واستعادة الحساب | شاشات كود صحيح/خاطئ/منتهي وإعادة إرسال، مصرح أنها معاينة | البريد الفعلي وVerifyEmail/ResetPassword؛ لا حفظ لكلمات المرور بالمتصفح |
| التنبيهات | قراءة فردية/الكل، فتح الزيارة، عرض حالة المقترح | الإشعارات الحقيقية والرد على التأخر ونقاط الاستدعاء المجدولة |
| الدفع | حالات مطلوب/معلق/فشل/مؤكد للعرض؛ لا يُمنح استحقاق فعلي | Moyasar ثم تحقق الخادم؛ لا اعتماد على redirect أو علامة من الفرونت |
| Google/Apple Calendar | رابط يدوي وملف ICS حسب الموعد المحدد فقط؛ واجهة حالة الربط والمزامنة | OAuth/status/sync لحسابات حقيقية؛ لا ادعاء connected قبل رد الخادم |
| الخصوصية | موافقات العرض افتراضيًا مغلقة ومحو البيانات المحلية | PrivacyConsent الفعلية والتحقق من الموقع/الصحة/التسويق |

## عقود الربط الجاهزة

`lib/backend-contract.ts` يضم أنواع الخطط والأنشطة والمستبعدين، تحليل participantVisitMemberIds (سلسلة JSON أو مصفوفة)، فحص مدد الأنشطة، وتطابق معرف اللعبة بواسطة sourceRideId. أضيفت مسارات API للتخطيط والاعتماد والتوقيت والسجل والدفع والتنبيهات والتحقق من الحساب. لا تستدعيها شاشة العرض تلقائيًا.

`normalizeStoredPlan` لا يخمّن الإكمال؛ تحتاج لاحقًا دمج VisitRecord/ActivitySession. يستخدم معرفات الأعضاء كهوية، لا أسماءهم. عند ربط الشاشات يجب تمرير تسميات الأعضاء والمنظم وهوية الحساب من الخادم بدل تبديل هوية العرض المحلي، وفحص نطاق المقترح من pendingProposal وrequiredApproverAccountId.

## ما لا يزال يحتاج تنفيذًا عند الربط

1. ربط تسجيل الدخول والجلسة/CSRF/CORS بعقد المصادقة المعتمد من الفريق. الباك الحالي يدعم Basic Auth؛ لا نخترع endpoint login غير موجود ولا نخزن كلمة مرور في localStorage.
2. استبدال تخزين العرض المحلي بزيارة ومعرفات حقيقية، وتوصيل الأحداث إلى backendApi، وإظهار loading/errors/unauthorized من الرد الفعلي.
3. جلب بيانات التوقيت والأهلية والانتظار والخريطة من الخادم وتحديثها؛ معاينة45د لكل لعبة ليست خوارزمية الخادم ولا بيانات حية.
4. ربط إنشاء طلب الدفع وواجهة Moyasar والتأكيد من الخادم، وإعداد OAuth وروابط الإنتاج والتقويم الفعلي.
5. ربط إرسال البريد وواتساب والتنبيهات الزمنية وGPS؛ أزرار العرض لا ترسل رسائل فعلية أو تثبت تتبعًا.
6. لوحة الإدارة الحالية معاينة كتالوج وليست CRUD إداريًا موصولًا؛ صلاحية ADMIN ونماذج التحرير الفعلية تحتاج مرحلة الربط.
7. الترجمة الإنجليزية الكاملة غير موجودة؛ النص الأساسي عربي. لا تمت إضافة زر لغة يوهم بترجمة غير مكتملة.
8. مواقيت الصلاة موضع عرض وتحذير حتى تصل من الخادم؛ لا توجد مواعيد صلاة محلية مصطنعة.

## التحقق

```bash
npm run typecheck
npm run check:flows
npm run build
```

الفحوص تغطي أولويات الألعاب والمدة والاستبعاد، استقلال SPLIT، الوجبات، صلاحيات المقترح والرفض والاعتماد، السجل لكل عضو، مسح حالة التكرار، وعقود المعرفات والتوقيت القادمة من الباك، إضافة لفحوص الفلو السابقة. المراجعة البصرية بالمتصفح في هذه الجولة تعذرت لأن عنوان المعاينة أعاد ERR_CONNECTION_REFUSED، رغم أن خدمة المعاينة أعلنت التشغيل. لذلك تبقى معاينة سطح المكتب والجوال الفعلية خطوة تحقق لازمة، ولا تعتبر فحوص المصدر إثباتًا لها.
