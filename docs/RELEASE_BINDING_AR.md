# نسخة الربط الفعلي

الواجهة الرئيسية تعمل الآن بطلبات الباك، ولا تقرأ زيارات أو حسابات `sikka-demo-v1`. التشغيل التجريبي القديم اختياري فقط عند تعيين `NEXT_PUBLIC_SIKKA_DEMO_MODE=true`، والقيمة الافتراضية ربط فعلي.

## الشاشات الموصولة

| الشاشة | مصدر البيانات/الإجراء |
|---|---|
| الدخول والخروج | Spring Security form login، جلسة JSESSIONID، `/account/me`، logout |
| إنشاء الحساب والتفعيل والاستعادة | account/register وauth verify/resend/forgot/reset |
| استكشاف الألعاب | ride/get؛ لا يفترض انتظارًا أو أهلية معروفة |
| الزيارات | my-visits/details/create/update-visit/cancel/delete/reuse |
| الدعوات والحضور | join، RSVP، رمز دعوة جديد، إزالة مشارك وفق الصلاحيات |
| العائلة | family-member CRUD وإضافة أفراد محفوظين إلى الزيارة |
| الأولويات | قراءة/حفظ preferences لكل عضو: rideId الحقيقي وMUST_RIDE/PREFERRED/OPTIONAL؛ لا answerStatus في الإدخال |
| البريكات | meal preferences، قراءة البريكات، اختيار مطعم بمعرّف Place الفعلي |
| المراجعة والاستحقاق | visit/preview، أسماء وحالة إجابات المشاركين، الفرص والسعر من الباك |
| التوليد وإعادته | generate/regenerate وrequestKey ثابت عند نتيجة شبكة غير مؤكدة؛ حالة المعالجة من plan-history |
| عرض الخطة | GROUP/INDIVIDUAL وفق الحساب، المستبعدات وأسباب الخادم، دون محاكاة محلية |
| الاعتماد وإعادة التخطيط | create approval/approve/reject وproposalKey؛ عرض الحالي والمقترح منفصلًا؛ المنظّم/المعتمد المطلوب من رد الخادم |
| الوصول والبدء والنهاية | arrival/start/complete؛ وقت الرياض، لا إكمال تلقائي للأنشطة المتبقية |
| التنفيذ والتقييم | ActivitySession وVisitRecord، الإكمال والتخطي والتصحيح، سجل كل عضو منفصل، تقييم الألعاب من VisitRecord والأماكن من ActivitySession |
| خريطة الخطة | خريطة نواف، معرّفات المصدر للعلامات، مسارات map-route/PER_MEMBER من الخادم؛ لا استبدال المسار المفقود بخط مصطنع |
| GPS | بدء جلسة GPS وتحديث الموقع بطلب المستخدم، مع capturedAt وموافقة الموقع؛ ليس تتبعًا دائمًا بالخلفية |
| التنبيهات | قائمة الخادم والقراءة والرد على التأخير وطلب تعديل |
| الخصوصية والملف | profile وprivacy-consent، حفظ/سحب الموافقة؛ تحديث الملف الأساسي لا يمسح بيانات صحية غير معروضة |
| تفضيلات الحساب | REPEAT/AVOID/NEUTRAL صريحة، منفصلة عن أولويات الزيارة |
| الإدارة | CRUD ألعاب ومرافق وقراءة الانتظار لحساب ADMIN؛ القيود والصلاحيات من الباك |
| الدفع | نموذج محمد Moyasar مع سعر وطلب من الباك، إعادة استخدام pending، تأكيد الدفع والمبلغ والعملة والمرجع من الباك |
| التقويم | manual/ICS وOAuth/status/sync عبر العميل الموثق |

## تغييرات الباك اللازمة لنفس الإصدار

- `/api/v1/auth/login`: POST form-urlencoded (`username`, `password`)؛ ينشئ الجلسة بدون إرجاع كلمة مرور أو تخزينها في الفرونت. Basic Auth ما زال يعمل لاختبارات API.
- logout يرجع JSON بدل redirect.
- رد Visit يتضمن organizerAccountId؛ الواجهة لا تستنتج المنظّم من أول اسم.
- GET `/api/v1/visit-member/preferences/{visitMemberId}` لقراءة الاختيارات المحفوظة؛ يرفض قراءة إجابات حساب آخر، ويقبل أفراد العائلة المُدارين فقط.
- حفظ الملف الأساسي يحافظ على healthData إذا لم ترسلها الواجهة.

## إعداد النشر

انشر الباك بهذا الإصدار أولًا، ثم الفرونت. لا تفعّل واجهة الربط مع باك قديم لا يحتوي login وقراءة الإجابات ومعرّف المنظّم.

الفرونت على Railway يبنى بـ `npm run build:railway` ويعمل بـ `npm run start:railway` كما في railway.json. متغيرات NEXT_PUBLIC تضبط قبل البناء:

```
NEXT_PUBLIC_SIKKA_API_URL=/api/backend
NEXT_PUBLIC_SIKKA_DEMO_MODE=false
NEXT_PUBLIC_MOYASAR_PUBLISHABLE_KEY=<مفتاح pk_test أو pk_live العام>
SIKKA_BACKEND_URL=<أصل الباك HTTPS أو عنوان Railway الداخلي مع المنفذ>
```

لا يوضع مفتاح Moyasar السري في الفرونت. خادم الباك يحتاج قاعدة البيانات وOPENAI_API_KEY ومفاتيح Moyasar والبريد/واتساب وGoogle الموجودة في إعداداته، وSPRING_PROFILES_ACTIVE=prod. يحترم الباك PORT، ومعه Dockerfile لـJava17 المطابق لـpom.xml. يجب تهيئة قاعدة البيانات الفعلية وشروط الألعاب وبيانات الانتظار؛ نجاح تشغيل السيرفر وحده لا يثبت جودة تلك البيانات.

بوابة الفرونت تمرر JSESSIONID فقط من الكوكيز، وتعيده بمسار `/` وHttpOnly وSameSite=Lax وSecure على HTTPS؛ لا تخزن كلمات المرور. تمنع طلبات Origin الخارجي، وتحافظ على رسائل 401/403. انتهاء الجلسة يعيد المستخدم للدخول ولا يعتبر بيانات الجهاز حسابًا صالحًا.

## التحقق وحدوده

- 80 اختبار باك نجح دون فشل، بما فيها جلسة دخول HTTP حقيقية والخروج وصلاحيات الإجابات وحفظ بيانات الملف.
- TypeScript وفحوص UI/food/planning وintegration وlive-flow.
- بناء Next للإنتاج واختبار HTTP لصفحات الإنتاج، وبوابة الدفع والجلسة مع باك محلي وهمي.
- تجميع كود الباك واختباراته نجحا. تغليف JAR لم يكتمل محليًا لأن maven-jar-plugin:3.5.1 غير موجود في الكاش ولا يتاح تنزيله في هذه البيئة؛ يجب تأكيد بناء Railway، وكذلك Dockerfile لأن Docker غير متاح هنا.
- لم يُنفذ خصم Moyasar أو 3DS فعلي في هذه الجولة، ولا إرسال بريد/واتساب فعلي، ولا مزامنة حساب Google جديد، ولا مراجعة بصرية تفاعلية للجوال. هذه نقاط قبول على بيئة النشر، وليست نتائج مؤكدة بهذه الفحوص.
- الإنجليزية الكاملة ليست ضمن هذه المرحلة؛ الواجهة عربية. إدارة الحسابات والمستخدمين العامة ليست شاشة الكتالوج الإداري الحالية.

لا توجد محاكاة صامتة عند تعطل الباك. الصفحات تظهر فشل الاتصال أو نقص البيانات بدل توليد خطة أو علامة دفع محلية.

## آخر تحديث للفريق

تمت مراجعة تحديث محمد `7cd2f0f`: فرق التحديث الفعلي رسالتا تأكيد بعد توثيق البريد والجوال. دُمجتا مع VerificationService الأحدث دون استبدال إصلاحات الأكواد والحدود الزمنية. شغل نواف وفرع shefo والأربع مزايا كان داخل main بالفعل.
